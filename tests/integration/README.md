# Integration

From the root, run `npm run build:contracts`, `npm run dev` and `npm run test:integration`. The local suites check RPC readiness, run the Phase 1 sponsored transfer and authorization mutation tests, run the P2 agent registry flow in `agent-flow.test.ts` with real controller, signer, new-signer and sponsor signatures ([results](../../docs/P2_VALIDATION.md)), and run the P3 verification flow in `verification-flow.test.ts` with real admin, provider, fixture-provider, controller and sponsor signatures ([results](../../docs/P3_VALIDATION.md)). The P3 suite serves agent metadata through an in-process transport because a local network cannot reach a public host; identities, signer accounts and publication are real. The P4 wallet flow in `wallet-flow.test.ts` deploys every contract, issues a test asset, and runs the SOW gate payment, rejections, pre-revocation signed payments, pause, replacement and an on-chain rollback with real owner, funder, agent and sponsor signatures ([results](../../docs/P4_VALIDATION.md)). The P5 payment flow in `payment-flow.test.ts` runs `examples/payment-flow.ts`, which drives the built CLI and submitter as separate processes, so run `npm run build` first; unlike the other suites it fetches agent metadata from a public host ([results](../../docs/P5_VALIDATION.md)). Shared local-network helpers live in `support/`; `support/wallet-world.ts` sets up the wallet environment for this suite and the adversarial suites.

`account-path.test.ts` (its scenario is in `support/account-path-scenario.ts`, shared with an opt-in Testnet run) pays from the real smart wallet as a custom account, through a sponsor that knows nothing of the wallet: a plain asset transfer, and a demo service in the service's own call. It shows that `execute` and the account path share one budget and that the service's request for an allowance is refused ([ADR 0007](../../docs/decisions/0007-account-payment-path.md)). `account-probe.test.ts` is the spike that preceded it, not an acceptance suite: it pays a plain asset transfer from the custom account in `tests/contracts/account-probe` ([ADR 0006](../../docs/decisions/0006-custom-account-spike.md)).

Empty executable suites fail.
